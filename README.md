# Cron Log Analyzer

A simple Python script that analyzes `journalctl` logs for the `cron` service, extracting and summarizing executed commands.

## Why I built this

While preparing for Linux systems administration practice (diagnosing services with `systemctl`, reading logs with `journalctl`), I wanted to go a step further than just running commands in the terminal, and build something that processed that data programmatically.

The sample log (`cron_log.txt`) was generated by running:

```bash
journalctl -u cron --no-pager > cron_log.txt
```

on a real Linux machine, after intentionally restarting the `cron` service to generate activity in the log.

## What the script does

1. Reads the log file line by line
2. Filters the lines corresponding to commands executed by `cron` (identified by the `CMD (` pattern)
3. Extracts the timestamp and the clean command from each line, discarding the rest (hostname, PID, log format noise)
4. Prints a summary with the total number of commands executed

## Example output
22:07:18 /bin/bash /root/Scripts/pull_vpns.sh
22:07:18 /bin/bash /root/Scripts/displayip.sh
22:09:01 [ -x /usr/lib/php/sessionclean ] && if [ ! -d /run/systemd/system ]; then /usr/lib/php/sessionclean; fi
Total commands executed: 3


## How to run it

```bash
python analyzer.py
```

(Requires `cron_log.txt` to be in the same folder as the script)

## What I learned

- File handling in Python (`open`, `with`)
- Processing unstructured text with `split()`, `rsplit()`, and `strip()`
- How `systemd`/`journalctl` centralize and expose service logs on Linux
- The difference between restarting a single service and a full system reboot (reflected in how `cron` handles `@reboot` jobs)

## Possible future improvements

- Run `journalctl` directly from Python (using `subprocess`), instead of relying on a manually generated file
- Detect anomalous patterns (e.g., the same command failing repeatedly)
- Group commands by script type
